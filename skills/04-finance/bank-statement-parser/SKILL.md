# Разбор банковской выписки

## Запуск в AI Studio

Скрипт ниже — файл командной строки, не отдельный API-инструмент. Выбери `shell` из инструментов текущего ответа и передай ему команду `python3` с фактическим путём к скрипту и входным файлам, используя схему именно этого инструмента. Сначала прочитай этот SKILL.md и проверь пути через shell; затем выполни команду, проверь код завершения и прочитай результаты. Необходимость вычислений не создаёт новых инструментов. Если shell отсутствует, сообщи, что автоматический разбор не выполнен; текстовый разбор не выдавай за запуск скрипта. Если API завершил ответ ошибкой инструмента, сообщи об ошибке: такой ответ не подтверждает выполнение задачи.

```bash
python3 <skill-dir>/scripts/parse_statement.py /app/statement.csv --out-csv /app/categorized.csv --report /app/reconciliation.md
```

Названия колонок сопоставляются без учёта регистра. Поддерживаются «Назначение платежа», «Сумма операции», «Приход»/«Расход» и другие явные синонимы. Для нестандартных колонок передай `--columns /app/columns.json`, например `{"description":"Операция","amount":"Итого","category":"Статья"}`.
Выбери профиль по задаче: `--profile business` — выписка бизнеса (выручка, поставщики, зарплата сотрудникам, ПО и сервисы); `--profile personal` — личные финансы (зарплата как поступление, продукты, жильё, транспорт, здоровье). Если контекст не указан, используется business; явно назови это допущение в результате. Подписки на ПО встречаются и у компаний, поэтому профиль определяет название статьи и смысл, а не только набор слов.

Приоритет категорий: заданная во входе → первое пользовательское правило → словарь профиля. Учитывается знак суммы: например, списание с пометкой «продажи» не становится выручкой. Пользователь может передать `--rules /app/rules.json` без изменения Python; формат и пример — в [assets/category_rules.example.json](assets/category_rules.example.json). Правило содержит `category`, массив буквальных строк `contains_any` (без учёта регистра/ё) и необязательное `direction`: `income`, `expense`, `any`. Первое подходящее правило побеждает, поэтому узкие правила ставь раньше широких. Названия контрагентов и категории добавляй по данным/правилам пользователя, а не по догадке о назначении перевода.

СБП, P2P и перевод с карты на карту определяют способ платежа, но не его экономический смысл. Без других признаков они получают «Переводы — назначение не уточнено»; неизвестные операции — «Прочее». Обе группы попадают в список для проверки. Перевод налога или зарплаты классифицируется по явному назначению, а не по слову «перевод». Не считай любой входящий перевод выручкой. Покажи профиль, долю операций для уточнения, соответствие колонок и общую сумму. CSV содержит `category_source`, суммы сохраняются независимо от распознавания.
Одна колонка суммы считается знаковой; в отдельных приходе/расходе расход вычитается. Если положительная сумма означает списание, уточни соглашение и нормализуй копию. Разные валюты нельзя суммировать без согласованного курса. Если валюта не указана, итог рассчитан при допущении одной денежной единицы: не называй валюту и не утверждай, что её единство проверено. «Сверка» здесь относится к арифметике выгрузки, а не к подтверждению банка или 1С.

## Данные и выполнение

Работай с текстом пользователя и загруженными файлами. Доступ к CRM, почте, 1С и другим корпоративным системам не требуется и не подразумевается.
Найди фактические файлы в контейнере; пути из примеров замени на реальные. Путь к скрипту определяется относительно прочитанного `SKILL.md`, а рабочие копии и результаты сохраняй отдельно в `/app` или `/tmp`.
Сначала посмотри заголовки и несколько строк. Если структура отличается, используй параметры сопоставления или подготовь нормализованную копию, показав соответствие полей. Не заменяй отсутствующие или нераспознанные значения нулями.
CSV читается как UTF-8, XLSX — локальным openpyxl из комплекта. Старый XLS требует экспорта в XLSX/CSV; смена расширения не конвертирует файл. Если вложение недоступно, сообщи, какой файл не найден; не анализируй вымышленные данные.
После запуска прочитай созданные файлы, сверь числа с входом и выдай краткий результат со ссылками на существующие артефакты. `manifest.json` содержит метрики и статус для следующего шага.
